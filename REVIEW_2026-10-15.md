# Performance, Usability & Multi-User Review — 2026-10-15

**Context assumed:** about 2,855 units in a 2 MB SQLite DB on an SMB share, several concurrent users (mostly schedulers and leads), and 1–3 SSRS imports per day.
**Status:** the quick wins below are fixed in the working tree (not committed). 510 tests pass, including new ones in `tests/test_review_fixes.py`, `tests/test_reload_edit_state.py` and `tests/test_identicals_export.py`.

## Measured (local copy of the real DB; SMB will be slower, so treat these as relative)

| Operation | Before | After |
|---|---|---|
| `status_color_name` over all units (runs on every sort, filter, calendar paint, alert build) | 130 ms | 4 ms |
| `load_units` (2,855 rows) | 52 ms | unchanged (fine) |
| Save one unit with **no** edits | 3 commits, 11–12 junk audit rows, `saved_by='local'` | 1 commit, only real changes, real username |
| Re-import an unchanged CSV | rewrites every row and bumps `updated_at` | rows reported as `unchanged`, untouched |
| Backups per import | 2 full copies | 1 |
| Backups per app launch | 1 full copy, every user, every launch | at most 1 per day |

Raw SQL is fast at this data size. Most of the slowness and hiccups come from: (a) doing things too often (rebuilds, reloads, backups, commits), and (b) multi-user state handling.

## Still open — ranked (not changed; these need a design decision or carry real risk)

### High
1. ~~Background reloads wipe unsaved inline-bar edits~~ — **fixed** (follow-up). The table rebuilds with signals blocked and restores the selection silently. A dirty inline bar keeps its edits and its original unit, including when the row is filtered out.
2. ~~A reload during an edit silently defeats optimistic locking~~ — **fixed** (follow-up). A dirty edit form keeps the unit it was opened from, so the save raises the conflict dialog. A "changed by another user" toast appears when the reload brings a newer version. Tests: `tests/test_reload_edit_state.py`.
3. **Shared `config.yaml` when the app runs from the share.** Startup always re-saves the merged config (`main.py`), so one user's `multi_user.username` can end up shared by everyone. Template changes (`ssrs_url`, schedules) also stop propagating because local always wins. Fix: keep per-user settings (username, `ui.*`) in `%APPDATA%` and treat the shared config as read-only. Make config writes atomic (temp file + `os.replace`).
4. **Reload storms.** `QFileSystemWatcher` reloads all units, then fully rebuilds the 2,700×9 `QTableWidget`, on every client after *any* user's save. The reload also re-parses tags on the UI thread. Fix: ignore changes caused by your own save, debounce 3–5 s, move tag parsing into `LoadWorker`, and longer-term replace the `QTableWidget` with a `QAbstractTableModel`.
5. **Synchronous DB reads on the UI thread.** These include audit "blame" on every row click, the pivot dashboard, and the conflict lookup. In rollback-journal mode on SMB each can freeze the UI for up to the 30 s busy timeout while an import holds the lock.

### Medium
6. **The Alerts view builds about 7 widgets per row** (1,500+ rows) with `setItemWidget`. Use a model/view with a delegate, or show only non-green units.
7. **Batch edit mutates live units before the save succeeds.** "Set status" in batch edit does nothing (the writer always persists the calculated color). Batch saves also overwrite `current_unit` and the form's unit.
8. **A batch save on a network blip shows one modal error per unit.** Collect failures into one summary.
9. **No `sys.excepthook`.** Any uncaught exception in a slot aborts the app (PyQt ≥5.5). Close does not wait for the feed-export, load or update workers.
10. **Import parsing edge cases:**
    - `1/15/2026 12:00:00 AM` dates are rejected.
    - `int("3.0")` fails for `build_cycle`.
    - Only UTF-8 is accepted (cp1252 or UTF-16 exports fail).
    - The import preview compares differently from the real import.
11. **The SSRS fetch can hang for minutes** with no progress or cancel (5 fallback methods × 60 s).
12. **Updater:**
    - It waits on *any* process with the exe name (other users on RDS), with no time limit.
    - It writes `version.txt` before the copy succeeds.
    - `deploy.py` overwrites the exe in place, so a client can copy a half-written file.
13. **Free-text in date columns is wiped on save.** For example, `dept_due_date_previous = 'eta 3/4'` is parsed to `None` and the next save overwrites it.
14. **The Alerts detailer combo shows "All Detailers" after a reload** while the list stays filtered. Toggling "show stale" drops the cancelled and Mfg-State filters.

### Low
15. Units assigned to former detailers (1,376 historical rows, e.g. "Ryan M", "Katie D") fail validation on *any* save. Allow the unchanged current value.
16. The refresh cooldown targets a button that doesn't exist (Refresh is a toolbar action) and leaks a timer.
17. The startup backup retention keeps the 7 newest files, not 7 days/4 weeks/3 months.

## Usability for schedulers — what would help most

- **A detailer × week remaining-hours grid.** This is the biggest gap for rebalancing. Today capacity shows only when one detailer is picked in Alerts, using a fixed 160 h threshold that ignores working days and due dates.
- **A right-click "Assign to ▸ {detailer}" menu** on list rows, including multi-select. Rebalancing currently takes about 5 clicks through Batch Edit.
- **Honest save feedback.** Show "Saving…" and then "✓ Saved" or "Failed". The UI currently shows "✓ Saved" before the background save finishes.
- **Persist list filters across sessions.** Make Clear Filters also reset Mfg State and Show Cancelled.
- **Global search shouldn't hijack focus.** A multi-match search currently jumps to List view and moves the cursor.
- **Show "Unassigned" in the Alerts detailer picker.**
